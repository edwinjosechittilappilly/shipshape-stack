# Plan: Title

- **Status:** Draft (Draft, Accepted, Implemented, Abandoned)
- **Author:** handle
- **Date:** YYYY-MM-DD
- **Issue:** #NNN
- **ADR:** link, if a decision was recorded

## Problem

What is wrong or missing today, for whom, and how do we know? Include evidence (user reports, metrics, incidents). No solutions here.

## Goals

- Observable outcomes that define success.

## Non-goals

- Things that are explicitly out of scope, so reviewers do not ask for them.

## Options

### Option A: name

How it works, pros, cons, cost.

### Option B: name

How it works, pros, cons, cost.

## Decision

The chosen option and the reasons it won. Include API shapes, data model changes, and diagrams where they clarify.

## Rollout

How this reaches users safely: feature flags, migration order (expand/contract), compatibility with the previous release,
configuration changes, and how to roll back.

## Test plan

Which behaviours are tested at which level ([testing guide](../testing.md)), including failure paths and any manual verification.
